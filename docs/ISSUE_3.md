# Issue #3 · Главная и стандартные письма Supabase

На главной одна бесконечная карусель — «Из мастерской». Верхнее изделие открывается по нажатию на фото или подпись. Для него используется первая запись публичной витрины после стабильной сортировки по доступности: готовые, доступные под заказ, будущие и остальные. Внутри группы действует порядок публичного каталога по дате создания и ID. Отдельного поля в Studio и миграции для этого правила не требуется. Снимок детали в первой карточке ленты используется при наличии второй фотографии.

Коллекции открываются через «В наличии», «Под заказ» и «Весь каталог». Индивидуальный проект и архив по-прежнему доступны с главной.

## Авторизация и проверки

Владелец подтвердил получение стандартного письма восстановления от рабочего Supabase. В локальной среде использовались стандартные письма Supabase Lite и собственный тестовый покупатель. Проверены регистрация, блокировка немедленной повторной отправки, повторная отправка через минуту, переход по ссылке, выдача роли customer и возврат в выбранную коллекцию. Проверены смена пароля по ссылке, отказ при повторном использовании ссылки и вход только с новым паролем.

Рабочий callback обменивает код PKCE на сервере. В локальном предпросмотре Supabase Lite по умолчанию возвращает сессию во фрагменте URL. Локальный обработчик направляет одноразовое доказательство из стандартного письма на серверную форму Roomlet. Подлинность и тип операции проверяет Supabase через verifyOtp. [Почтовая авторизация](EMAIL_AUTH.md)

Существующие локальные owner и maker вошли в Studio. Управление командой вернуло владельцу HTTP 200, мастеру — HTTP 404. Прошли ESLint, TypeScript, 28 модульных и PostgreSQL-тестов, HTTP-проверка магазина, интеграционная проверка почты и обе сборки. Полный Playwright-раннер в оболочке Codex остановился с `spawn EPERM` до первого сценария. Для запуска на Windows используйте `.\supabase\demo\test-e2e.ps1` из обычного PowerShell в корне Roomlet.
