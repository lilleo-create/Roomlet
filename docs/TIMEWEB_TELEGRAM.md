# Тестовый стенд Roomlet на Timeweb Cloud

## 1. Поднять магазин с SSR

Откройте существующее приложение в App Platform. Проверьте репозиторий `lilleo-create/Roomlet`, ветку `feature/backend-studio`, корень проекта и режим Next.js с SSR. Технический адрес стенда — `https://lilleo-create-roomlet-ec4d.twc1.net`. Для этой настройки достаточно уже приобретённого приложения. [Next.js в Timeweb](https://timeweb.cloud/docs/apps/deploying-frontend-apps/nextjs)

1. Выберите Node.js 22 с версией не ниже 22.13.0. Локальная проверка выполнена на 22.21.1. В логе сборки проверьте фактическую версию через `node --version`.
2. Если панель позволяет задать установку зависимостей, укажите `npm ci --include=dev`. Для сборки укажите `npm run build` и `ROOMLET_SMALL_BUILD=true`, для запуска — `npm start -- -H 0.0.0.0`. По умолчанию Next слушает порт 3000 или использует предоставленную платформой переменную `PORT`. Указанный в панели порт должен совпадать с портом процесса. В логе должен появиться список динамических маршрутов и затем готовность Next к приёму запросов.
3. Добавьте переменные из таблицы как локальные для приложения. Переменные для Auth нужны запущенному SSR-процессу. После изменений запустите новый деплой и проверьте его SHA. [Переменные App Platform](https://timeweb.cloud/docs/apps/variables)

| Имя | Значение для стенда |
| --- | --- |
| `ROOMLET_SITE_URL` | `https://lilleo-create-roomlet-ec4d.twc1.net` без слеша в конце |
| `NEXT_PUBLIC_SUPABASE_URL` | URL выбранного тестового проекта Supabase |
| `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` | Publishable key **того же проекта** |
| `ROOMLET_SMALL_BUILD` | `true` при сборке, один рабочий процесс |
| `ROOMLET_DEMO_MODE` | `false` |
| `ROOMLET_TELEGRAM_ENABLED` | Сначала `false`. Включить на шаге 4 |
| `ROOMLET_TELEGRAM_SIGNING_KEY` | Секрет сервера. RSA PKCS#8 PEM, целиком закодированный в Base64 |
| `ROOMLET_TELEGRAM_BOT_TOKEN` | Секрет сервера. Токен существующего `@roomlet_shop_bot` из BotFather |
| `SUPABASE_SECRET_KEY` | Серверный secret key тестового проекта, только для вызова RPC погашения запуска |

Секреты храните в менеджере паролей и полях переменных Timeweb. Не включайте их в `NEXT_PUBLIC_*`, команды деплоя, Git, переписку или скриншоты. В PowerShell следующая команда создаёт отдельный ключ подписи и копирует его в буфер обмена. Сохраните его в менеджере паролей, вставьте в нужное поле, затем очистите буфер. Используйте постоянный ключ между деплоями.

```powershell
node -e "const {privateKey}=require('node:crypto').generateKeyPairSync('rsa',{modulusLength:3072}); process.stdout.write(Buffer.from(privateKey.export({type:'pkcs8',format:'pem'})).toString('base64'))" | Set-Clipboard
```

В терминале SSR-контейнера выполните `node scripts/check-runtime.mjs`. Если терминал недоступен, на время диагностики задайте команду запуска `node scripts/check-runtime.mjs && npm start -- -H 0.0.0.0`. Проверка выводит версию Node, наличие параметров и HTTP-статусы Auth и каталога без значений ключей. После диагностики верните обычную команду запуска.

## 2. Проверить Supabase

1. Войдите в **тестовый** проект. Для нового тестового проекта примените миграции из `supabase/migrations` в порядке имён. Если предыдущие миграции уже применены, добавьте только `20261127210548_telegram_launch_redemption.sql`. Сверьте историю в панели. Для применения к рабочему проекту Roomlet требуется отдельное согласование.
2. С выключенным Telegram откройте каталог и войдите существующим тестовым владельцем в Studio через почту. При пустом каталоге магазин должен показать пустое состояние. Страница ошибки или голая шапка при HTTP 200 означает, что SSR ещё требует диагностики. Проверьте лог приложения и переменные **запущенного процесса**. В разделе Authentication → URL Configuration тестового проекта задайте Site URL стенда и разрешите используемые приложением адреса `/profile/confirm` и `/profile/recover` с нужными параметрами перехода. Проверьте тестовую доставку на разрешённый адрес.
3. Откройте `/.well-known/openid-configuration` и `/api/telegram/jwks` на стенде. Оба должны вернуть JSON с HTTP 200. Проверьте точный issuer, URL JWKS и публичный ключ RSA с полями `n`, `e`, `kid`. Это работает с выключенным входом после установки ключа подписи. Код 503 означает, что серверу требуется корректный ключ или origin.
4. В Supabase Authentication → Sign In / Providers добавьте **custom OIDC**. Identifier — `custom:roomlet-telegram` (если форма уже показывает префикс, введите `roomlet-telegram`). Client ID — `roomlet-mini-app`, issuer — адрес стенда, scopes — `openid profile`. Включите опцию `email_optional`, оставьте проверку nonce включённой. Для обязательного поля Client Secret сгенерируйте отдельный случайный секрет в менеджере паролей. Нативный обмен ID-токена использует JWKS и аудиторию. Включите manual identity linking в настройках Auth тестового проекта. Проверьте доступную квоту custom providers до подтверждения изменений. [Custom OIDC](https://supabase.com/docs/guides/auth/custom-oauth-providers) · [Привязка идентичности](https://supabase.com/docs/guides/auth/auth-identity-linking)

## 3. Настроить существующего бота

1. В Telegram откройте официальный `@BotFather` → `/mybots` → `@roomlet_shop_bot`. Убедитесь, что выбран нужный бот. Сохраните текущие настройки Main Mini App и кнопки меню, если они уже используются.
2. В настройках **Main Mini App** задайте URL `https://lilleo-create-roomlet-ec4d.twc1.net/mini`. В **Menu Button** укажите тот же адрес и подпись «Открыть магазин». Используйте кнопку Mini App, а не простую ссылку на сайт. Для запуска не требуются webhook бота и отдельный процесс polling. [Telegram Mini Apps](https://core.telegram.org/bots/webapps)
3. Веб-вход через официальный Telegram Login представляет отдельную интеграцию с Authorization Code, PKCE, проверкой issuer, audience и nonce. Mini App получает другое доказательство — подписанный запуск. На этом этапе обычный браузер использует действующий вход по почте. Redirect-вход через OIDC-посредник выключен. [Telegram Login](https://core.telegram.org/bots/telegram-login)

## 4. Включить вход и проверить на Samsung

1. После настройки Supabase и BotFather переключите `ROOMLET_TELEGRAM_ENABLED=true` на тестовом стенде и передеплойте. Для остановки новых обменов верните `false` и передеплойте. Ранее выданными сессиями управляет Supabase Auth.
2. Для привязки существующего владельца **первым открывайте** `https://t.me/roomlet_shop_bot?startapp=link` (та же ссылка в настройках профиля). В WebView войдите по почте владельца, проверьте адрес, нажмите «Подтвердить привязку». Если вход по паролю старше пяти минут, подтвердите его заново. Обычный первый запуск до привязки может создать отдельного покупателя. Занятую идентичность приложение автоматически не переносит.
3. Сверьте UUID и роль до и после привязки в Supabase. Проверьте повторный вход по почте и доступ к Studio. В другой тестовой сессии мастера проверьте его разрешённые разделы. Используйте учётные записи именно этого окружения.
4. На Samsung откройте главное приложение бота с отдельным Telegram тестового покупателя. После автологина должен открыться магазин. Выйдите, закройте WebView полностью, запустите заново. В Auth должен остаться тот же UUID и одна Telegram-идентичность с ролью покупателя в `profiles`. Для проверки конфликта используйте только тестовые аккаунты. Протухший запуск или повторное погашение требуют закрыть и заново открыть Mini App.
5. Запишите версию Telegram/Android, SHA, результаты входа, ссылки и роли. Не сохраняйте в отчёте initData, содержимое cookies, пользовательские токены и персональные идентификаторы.

## Локальные проверки

Выполните `npm run lint`, `npm test`, `npm run build`, затем `node tests/integration/telegram-http.mjs` и `node tests/integration/store-http.mjs`. HTTP-тест Telegram использует настоящий обработчик Next и Supabase JS, одноразовый ключ подписи и локальную подмену HTTP-ответа Auth. SQL-тест отдельно проверяет права и однократность реальной функции PostgreSQL. Окончательная проверка выдачи сессии облачным Auth требует настроенного провайдера и запуска из Telegram.

## Проверка 28 ноября 2026

На Node 22.21.1 локально прошли сборка Next 16.4.6 с одним процессом генерации страниц, TypeScript, ESLint, 31 тест и обе HTTP-проверки. В изолированном демомагазине проверены фактический вход по паролю и чтение роли для владельца и мастера, а также открытие их панели Studio. Из локального окружения рабочий Supabase ответил HTTP 200 для Auth Settings и RPC каталога с publishable key.

При первичной проверке технического адреса HTTP перенаправлял на HTTPS. После завершения TLS главная отдала оболочку Roomlet c ошибкой SSR, а Studio вернула 500. Для диагноза нужны runtime-лог и состав переменных именно запущенной версии. Приёмка облачной сессии Telegram, привязки существующего владельца и запуска на Samsung требует тестового провайдера и настроенного бота.
