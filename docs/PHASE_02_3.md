# Phase 02.3 · Мобильная витрина и вход

Рабочая ветка — `feature/backend-studio`. Исходная версия для сравнения — Phase 02.2, коммит `7335343`. Снимки сделаны во внутреннем браузере с локальных серверов Roomlet.

## Что изменилось

- На главной две строки заголовка, короткое объяснение про готовые и заказные миниатюры, одна основная кнопка и крупный снимок. Сразу после него доступны «Готовые работы» и «Сделаем на заказ». Индивидуальный проект имеет отдельный переход с текущим статусом приёма. При пустом каталоге показывается редакционная иллюстрация материалов мастерской. [Рабочая главная](screenshots/phase-02-3/after-working-home-390.jpg)
- У фильтров доступности одна горизонтальная строка. На ширине 320 px её видимая область составила 289 px при ширине содержимого 478 px. Выбор крайнего фильтра с клавиатуры прокрутил строку и показал проданный экземпляр.
- В гостевом профиле есть вход и создание аккаунта. Формы поддерживают проверку полей, показ пароля, состояние отправки, ответ об ошибке и подтверждение. На desktop Escape возвращает на предыдущий уровень; при фокусе в текстовом поле пользователь продолжает редактирование.
- Для почтовой регистрации нужны email и пароль. Имя необязательно. Проверенный аккаунт вернулся в `/catalog?availability=made`, где осталась выбранной категория доступности «Под заказ». Сервисные уведомления и согласие на маркетинг сохраняются отдельно от регистрации. [Модель аккаунта](ACCOUNT.md) · [Почтовые шаблоны](EMAIL_AUTH.md)
- Для Mini App реализована серверная проверка целостности и свежести Telegram `initData`. Подготовлена архитектура, объединяющая официальный Telegram OIDC веб-версии и запуск Mini App вокруг существующего UUID Supabase. На текущем этапе Telegram-сессии не выдаются. Для включения нужны HTTPS, настройка BotFather, OIDC-посредника, callback и интеграционные проверки в тестовом окружении. [Telegram и Supabase](AUTH_TELEGRAM.md)
