# Phase 02 · проверка и передача
Ветка feature/backend-studio создана от принятого прототипа 49bea5b. Пакеты @supabase/supabase-js 2.119.2, @supabase/ssr 0.12.7 и sharp 0.35.5 зафиксированы в package-lock.json. Официальные навыки supabase/agent-skills установлены в .agents/skills из ревизии c9be0e931b7930f7d02126d04774d904c381e7d7.

| Проверка | Результат |
| --- | --- |
| ESLint, TypeScript, production build | Успешно |
| npm test | 17 проверок по отчёту Node test runner. Правила валют, условия публикации, оптимизация фотографий, доступность и исполнение SQL |
| PostgreSQL и RLS | Реальная миграция исполнена в PGlite с минимальными таблицами систем Auth/Storage. Проверены роли anon, customer, maker, запрет самостоятельного назначения роли, закрытые расходы и заказы, доступ к фото, публикация, архив, удаление и отклонение устаревшей записи |
| Настройки мастерской | После смены на Asia/Tokyo и JPY получены 70 дат, вычет дневного резерва и ноль минут на заблокированной дате. Публичный вызов не раскрывает причину блокировки |
| HTTP-интеграция | Next production + настоящий Supabase SDK + локальные ответы PostgREST/Storage. Каталог обработал пустое состояние, публикацию, смену цены и фотографии, архив и ошибку backend. Ответ фотографии WebP; старые пути и музейное фото в рабочем режиме возвращают 404 |
| Подключение к указанному проекту | Реальный Auth API вернул HTTP 200 с предоставленным publishable key. Функция roomlet_catalog на момент проверки отсутствовала, PostgREST ответил 404 PGRST202 |
| Сквозные тесты Playwright | Runner обнаружил 12 сценариев. Windows вернула spawn EPERM при запуске worker до исполнения тестов. Авторизованный сценарий на реальном телефоне остаётся приёмочной проверкой после подключения базы |

На рабочем проекте не менялись схема, записи Auth и содержимое Storage. Текущий Supabase-коннектор не получил доступ к управлению указанным проектом. Для завершения подключения администратор применяет миграцию и назначает конкретной учётной записи роль. [Инструкция по развёртыванию](SETUP.md).

Сохранение параметров карточки, количества экземпляров, цены, себестоимости и ссылок на медиа атомарно в PostgreSQL. Отправка бинарных файлов в Storage предшествует транзакции. Неопределённый результат сетевого запроса может оставить невостребованный файл. [Порядок проверки и очистки](INVENTORY.md).

Фотографии музея, демонстрационная корзина и образцы заказов Phase 01 не являются данными рабочего магазина. Полноценный Booking, заказы и платежи остаются следующими этапами.
