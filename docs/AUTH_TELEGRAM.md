# Идентификация Telegram в Roomlet

Существующая учётная запись Roomlet определяется UUID Supabase Auth. Авторизацию в Studio по-прежнему определяет роль в `profiles`. Для настройки тестового стенда, бота и привязки владельца см. [инструкцию Timeweb](TIMEWEB_TELEGRAM.md).

## Автоматический вход в Mini App

Бот открывает `/mini`. На этом маршруте официальный SDK Telegram отдаёт полную строку `WebApp.initData`. Браузер отправляет её в теле запроса на `/api/telegram/session` со своего origin. Сервер сверяет origin с настроенным HTTPS-адресом, проверяет HMAC подписи с токеном бота, допустимый возраст и числовой Telegram ID. Срок запуска — пять минут с допуском 30 секунд на опережение часов. [Проверка Telegram](https://core.telegram.org/bots/webapps#validating-data-received-via-the-mini-app)

Перед выдачей удостоверения сервер вызывает `consume_telegram_launch`. Уникальный индекс PostgreSQL разрешает только одно погашение, включая одновременные запросы и перезапуски приложения. Просроченные записи очищаются при последующих погашениях. В журнале остаются только хеш и срок. Если база недоступна или обмен оборвался после погашения, пользователь открывает приложение заново для получения нового запуска.

Roomlet выдаёт исключительно своему серверному клиенту короткоживущий ID-токен RS256. Issuer привязан к HTTPS-стенду, audience — `roomlet-mini-app`, sub — `tg:<числовой Telegram ID>`. Срок — до минуты и не дольше оставшегося времени запуска. В токене — SHA-256 случайного nonce. Roomlet передаёт nonce и подпись в `signInWithIdToken` custom OIDC провайдера. Supabase проверяет их и создаёт обычную SSR-сессию. Секретный ключ Supabase используется исключительно для погашения запуска. Браузер получает стандартные сессионные cookies. [Обработчик нативного обмена в Supabase Auth](https://github.com/supabase/auth/blob/master/internal/api/token_oidc.go)

Публичные endpoints discovery и JWKS позволяют Supabase проверить подписанта. Зарезервированный redirect endpoint отклоняет OAuth-запросы. Веб-версия продолжает использовать почту. Для будущего веб-входа через официальный Telegram Login понадобится зарегистрировать callback в BotFather, проверить ID-токен Telegram и сопоставить его проверенный числовой ID с тем же субъектом. [Telegram Login OIDC](https://core.telegram.org/bots/telegram-login)

## Привязка

Параметр запуска `link` только выбирает экран. Пользователь входит в свой аккаунт по почте и подтверждает привязку в WebView. Сервер проверяет User UUID через Auth, ожидаемый UUID экрана и подтверждённый метод password в AMR за последние пять минут. Только затем он вызывает `linkIdentity` в существующей сессии. Название, username и контакты исключены из сопоставления. Активная сессия сама по себе не запускает привязку. Конфликт двух UUID требует отдельного разбора владельцем.

Функция создания профиля выдаёт новым пользователям роль customer. Telegram-удостоверение содержит только стабильный субъект и, при наличии, отображаемое имя. Роли, email, права и адрес доставки в него не включаются. Выбранное в Roomlet имя имеет приоритет. [Привязка в Supabase](https://supabase.com/docs/guides/auth/auth-identity-linking)
