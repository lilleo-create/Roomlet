# Подключение мастерской
Рабочий проект: `chugicqwtdmqqxujfyvz`. Сервер приложения использует URL и publishable key из `.env.local`. Сессия подтверждается Supabase Auth, доступ к таблицам и Storage проверяется политиками PostgreSQL. Приложению не нужен service role key.

## Схема
Перед изменением рабочего проекта проверьте список существующих миграций, таблиц, bucket и политик Storage. Скрипт рассчитан на отсутствие объектов Roomlet с такими же именами. При совпадении имён сопоставьте имеющуюся схему с миграцией и подготовьте отдельное согласованное изменение. Не удаляйте существующие таблицы ради первого запуска.

Предпочтительный путь с настроенным Supabase CLI и правами проекта:

```sh
supabase login
supabase link --project-ref chugicqwtdmqqxujfyvz
supabase migration list
supabase db push --dry-run
supabase db push
```

В списке к применению должна быть только ожидаемая миграция из `supabase/migrations`. Для SQL Editor используйте файл целиком в транзакции и согласуйте историю миграций CLI перед следующим развёртыванием. Схема создаёт таблицы приложения, RLS, приватный bucket и внутренние функции. Предсуществующие записи Auth получают профиль customer. Проверьте, что PostgREST публикует схему public, а roomlet_private отсутствует в списке exposed schemas. В Supabase Storage убедитесь, что пользовательские глобальные политики проекта не дают публичный доступ в приватные bucket.

## Первая учётная запись
1. В Authentication → Users создайте или выберите подтверждённую учётную запись для входа через email/password. У существующей записи должен быть установлен пароль. Скопируйте UUID конкретного пользователя.
2. Выполните в SQL Editor как администратор, заменив маркер на проверенный UUID. Для мастера достаточно maker. Используйте owner для владельца.

```sql
update public.profiles
set role = 'maker'
where id = '<UUID пользователя>'::uuid
returning id, role;
```

Результат должен содержать ровно одну строку. Новому пользователю роль customer назначается автоматически. Поля пользовательского metadata не участвуют в предоставлении доступа. Для отзыва доступа мастерской верните роль customer.

## Проверка подключения
Откройте магазин без входа. В новой базе каталог пуст. Подтвердите вход в Studio, создайте черновик и проверьте его отсутствие в магазине. Опубликуйте изделие с фотографией и проверьте его в отдельном окне без входа. Затем снимите с публикации и повторно откройте карточку и прежний URL фотографии. В настройках закройте период и проверьте изменение публичной доступности. /api/availability отдаёт только дату и доступные минуты. Отсутствие функций roomlet_catalog или roomlet_availability означает, что миграция не применена либо не попала в кэш схемы PostgREST.
