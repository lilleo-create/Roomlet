# Управление ассортиментом

После входа с ролью owner или maker откройте **Studio → Изделия → Создать изделие**. В карточке есть категории (кнопка «+» создаёт новую), описание, размеры, материалы, количество свободных готовых экземпляров, изготовление под заказ, эскиз, себестоимость и плановое время. Поле трудозатрат принимает минуты. Цена и себестоимость вводятся в выбранной валюте: число допустимых десятичных знаков зависит от валюты (например, 2 для RUB, 0 для JPY, 3 для KWD). Суммы сохраняются целыми числами минимальных единиц.

Первое сохранение создаёт черновик. При выборе статуса «Опубликовано» необходимы категория, положительная цена, фотография и хотя бы один доступный способ покупки. Переход обратно в черновик снимает публикацию. Статус «В архиве» оставляет карточку доступной мастеру. Удаление требует отдельного подтверждения; при связях с заказами или производством используйте архив.

Каждая карточка поддерживает до 12 фотографий, исходный файл — до 24 МБ. JPEG и PNG поддерживаются в современных мобильных браузерах. Для HEIC требуется встроенный декодер браузера. Первая фотография становится обложкой. Во время сохранения фото последовательно сжимаются до WebP (длинная сторона до 1600 px, максимум 300 КиБ на фото); сервер декодирует полученные файлы, удаляет метаданные и повторно кодирует WebP. Стоит добавлять подписи для слабовидящих посетителей.

Файлы получают случайные имена в приватном bucket product-media. Данные карточки, остатки, цены и список медиа фиксируются одной транзакцией save_product с проверкой версии. Если другой мастер изменил запись, обновите страницу и сверяйте значения. При ответе сервера с неопределённым исходом сначала откройте карточку заново. Для оборудования с нестабильной сетью важно дождаться подтверждения сохранения.

После удаления или замены фото приложение очищает снятые объекты через Storage API. При прерывании между загрузкой и фиксацией или после сбоя очистки в приватном хранилище могут остаться неиспользуемые файлы. Для обслуживания сверяйте кандидатов с product_media.storage_path под учётной записью администратора. Перед ручной очисткой завершите операции редактирования и повторно проверьте ссылки; удалять файлы следует через Storage API. Не удаляйте записи напрямую из storage.objects.

Браузерный тест e2e/inventory-local.spec.ts предназначен для отдельного локального Supabase с применёнными миграциями. Задайте NEXT_PUBLIC_SUPABASE_URL с loopback-адресом, publishable key и тестовые ROOMLET_LOCAL_MAKER_EMAIL / ROOMLET_LOCAL_MAKER_PASSWORD. Соберите и запустите приложение с этим же локальным backend. Тест создаёт собственную карточку, загружает изображение, проверяет публикацию от имени посетителя, архивирует и удаляет тестовую карточку. При пустом справочнике он оставляет тестовую категорию «Проверочные модели» для следующих прогонов.
