# Аккаунт и онбординг Roomlet

Гость может открыть витрину, каталог и страницу изделия. В профиле доступны вход и регистрация. Для веб-версии основной запланированный способ — официальный Telegram Login, для Telegram Mini App — автоматический вход по проверенному запуску. Сейчас действует почта и пароль. Интерфейс показывает доступность Telegram до начала действия. [Устройство интеграции Telegram](AUTH_TELEGRAM.md)

## Вход по почте

- При регистрации нужны почта и пароль. Имя можно раскрыть и заполнить отдельно. Приложение вызывает Supabase Auth `signUp`. Триггер базы создаёт профиль с ролью `customer`.
- Если проект требует подтверждения, человек переходит по письму в исходном браузере или вводит код из письма. До подтверждения интерфейс не сообщает об открытии сессии. В изолированной демобазе подтверждение регистрации отключено. Уже вошедшему пользователю доступны редактирование имени и выход.
- Параметр `next` сохраняет разрешённый путь, например `/profile/settings` или `/catalog?availability=made`. Формы переносят назначение между входом, регистрацией и восстановлением. Внешние адреса и административные маршруты приводят в профиль.
- Восстановление начинается с адреса почты. Ссылка PKCE использует браузер, который запросил письмо. В качестве альтернативы пользователь может ввести почту и одноразовый код из шаблона. Временная recovery-сессия отделена от основной. После успешной смены пароля доступен обычный вход.
- В настройках Supabase Auth задайте Site URL и разрешённые Redirect URLs для `/profile/confirm` и `/profile/recover`. На размещённом сайте для ссылок в письмах задайте доверенный HTTPS-адрес `ROOMLET_SITE_URL`. Настройте доставку и шаблоны подтверждения и восстановления. Ссылка использует `{{ .ConfirmationURL }}`, для ручного ввода добавьте в текст письма `{{ .Token }}`. Используйте проверенный домен SMTP перед публичной рассылкой. [Почта и пароль в Supabase](https://supabase.com/docs/guides/auth/passwords) · [Шаблоны писем](https://supabase.com/docs/guides/auth/auth-email-templates)
- Из вложенных страниц профиля на большом экране можно выйти по Escape. В текстовом поле, открытом диалоге или на мобильном устройстве продолжает действовать обычное поведение. Видимая ссылка возврата доступна на любой ширине.

## Модель данных

| Поле | Источник и назначение |
| --- | --- |
| ID | Постоянный UUID `auth.users.id` и связанный с ним `profiles.id`. Добавление способа входа сохраняет UUID. |
| Email, состояние подтверждения | Supabase Auth хранит email и `email_confirmed_at`. Для будущего Telegram-аккаунта почта может отсутствовать. |
| Имя и роль | `profiles.display_name` доступно для изменения самим пользователем. `profiles.role` проверяют сервер и RLS. Параметры Telegram и имя в форме не предоставляют доступ к Studio. |
| Даты | `profiles.created_at` и `updated_at` фиксируют создание и обновление профиля. |
| Telegram | Проверенный числовой ID и identity провайдера связываются с UUID. Отображаемое имя, фото, язык и `telegram_username` могут отсутствовать или меняться. Пока интеграция выключена, эти данные не собираются. |
| Язык и часовой пояс | Будущие необязательные поля `locale` и `timezone` профиля. Часовой пояс мастерской хранится отдельно. |
| Уведомления | `notification_preferences.profile_id` принадлежит одному аккаунту. `order_updates` и `marketing_opt_in` по умолчанию выключены. |
| Согласие на маркетинг | Отдельный выбор на странице уведомлений. В приватном журнале сохраняются UUID, решение, версия текста и серверное время при выдаче или отзыве согласия. Повторное сохранение того же решения не создаёт запись. Отправка кампаний в этот этап не входит. |
| Данные доставки | Имя получателя, телефон, страна, город, адрес и предпочтительный способ связи будут собираться при оформлении конкретного заказа. Бюджет и описание проекта относятся к брифу. |

## Миграция уведомлений

Миграция `20261127170619_account_notifications.sql` добавляет таблицу предпочтений, политику доступа к своей записи, функцию сохранения и закрытый журнал согласий. Применяется автоматически к локальному Supabase при запуске `npm run demo:dev`. Для рабочего проекта предусмотрено отдельное применение миграции перед использованием страницы уведомлений. До этого приложение сообщает о временной недоступности настроек. Сервер продолжает читать роли из существующей `profiles`.
