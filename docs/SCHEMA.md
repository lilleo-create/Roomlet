# Схема Phase 02
Базовая миграция — `20261127131031_roomlet_backend_studio.sql`. Она создаёт новые объекты приложения, не переиспользует существующие одноимённые таблицы и не удаляет ранее созданные данные.

| Таблицы | Назначение |
| --- | --- |
| profiles | Профиль с FK на auth.users. Новая учётная запись получает customer. Первого владельца назначает администратор проекта. Владелец выдаёт роль maker через Studio |
| categories, products | Категория, постоянный slug и характеристики модели. Статусы draft, published, archived |
| product_media | Порядок, альтернативный текст и путь к объекту в приватном bucket product-media |
| product_units, product_offers | Физические экземпляры и их состояния. Цена, валюта, изготовление под заказ и необходимость эскиза хранятся отдельно от запаса |
| product_costs | Закрытые себестоимость и плановые минуты. Себестоимость хранится в валюте предложения |
| workshop_settings, working_hours, blocked_periods | Одна мастерская, её часовой пояс, валюта и резерв, минуты по дням недели и закрытые интервалы с причиной |
| orders, order_items, custom_requests | Основа для заказов, состава заказа, предварительной оценки и индивидуальных запросов |
| production_jobs, production_updates | Работы по изготовлению и история обновлений |
| analytics_events, content_drafts | События и черновики контента для следующих этапов |

## Границы доступа
RLS включена на всех 17 прикладных таблицах. Анонимная витрина получает только данные функций roomlet_catalog() и roomlet_availability() и снимки опубликованных моделей по политикам Storage. За статус публикации, количество доступных экземпляров и выбор публичных полей отвечает SQL. Сессия покупателя может читать собственный профиль. Доступ к заказам, рабочим настройкам и закрытым расходам ограничен сотрудниками. При добавлении пользовательской истории заказов понадобятся отдельные политики владения.

Внутренние привилегированные функции находятся в roomlet_private и используют фиксированный search_path. Запись товара и подтверждение удаления требуют роли мастера или владельца; прямое изменение роли пользователем запрещено. На клиент передаются только разрешённые поля и метаданные изображений. Контур приложения работает с publishable key и текущей сессией.

## Согласованность
Цены и себестоимость представлены bigint в младших единицах валюты. Для предложения хранится буквенный код ISO 4217. Количество десятичных знаков определяется валютой. Количество готовых экземпляров вычисляется по строкам product_units со статусом available. Транзакция изменения карточки сериализует записи одной модели и проверяет expected_updated_at. Промежуточное состояние публикации не видно магазину. Условия использования фото и очистка файлов описаны в INVENTORY.md. Индексы покрывают внешние ключи и выборки опубликованных моделей, запасов и интервалов блокировки.

## Управление командой

Миграция `20261127161912_roomlet_team.sql` добавляет три RPC для владельца. `roomlet_team_members()` возвращает список участников мастерской. `roomlet_grant_maker(p_email)` выдаёт роль мастера подтверждённому аккаунту. `roomlet_revoke_maker(p_user_id)` возвращает ему роль покупателя. При каждом вызове проверяется текущая роль в `profiles`. Триггер защищает последнего владельца от понижения и удаления. Авторизованный пользователь может менять `display_name` только у собственного профиля. [Настройка приглашений](SETUP.md#команда-мастерской)
