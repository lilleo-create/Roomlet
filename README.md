# Roomlet · Phase 02
Roomlet Store и Roomlet Studio используют один проект Next.js и один каталог Supabase. Мастер открывает `/studio` напрямую с телефона, входит с электронной почтой и паролем и управляет изделиями. Публичная витрина читает опубликованные карточки при запросе. Базовая версия прототипа сохранена в коммите `49bea5b`, ветка разработки — `feature/backend-studio`.

## Подключение
1. Используйте Node.js 22.13+ и выполните `npm ci`. Скопируйте `.env.example` в `.env.local`, задайте URL проекта и его publishable key. Для рабочей витрины оставьте `ROOMLET_DEMO_MODE=false`.
2. Примените миграцию и назначьте роль мастеру по [инструкции подключения](docs/SETUP.md). Для первой настройки нужны права администратора конкретного проекта Supabase.
3. Выполните `npm run dev`. Откройте [магазин](http://localhost:3000) или [вход в Studio](http://localhost:3000/studio). На телефоне используйте адрес доступного ему сервера. Для установки на хостинг выполните `npm run build` и `npm start`, задав те же переменные среды на сервере.

## Первый товар
Войдите в Studio, откройте «Изделия», создайте карточку и добавьте фотографии. Укажите категорию, цену, запас готовых экземпляров или возможность изготовления. Сохраните черновик, проверьте карточку и опубликуйте. Изменения видны при следующем открытии каталога. В «Сегодня → Настройки мастерской» задаются часовой пояс, валюта, рабочие часы по дням недели, резерв и периоды недоступности.

## Режимы
Рабочая витрина показывает пустое состояние, когда опубликованных изделий нет, и отдельное сообщение при ошибке Supabase. Музейная демонстрация включается флагом `ROOMLET_DEMO_MODE=true` на сервере. Studio в обоих режимах требует настоящей учётной записи с ролью owner или maker. Создание реальных заказов, платежи и серверное резервирование относятся к следующим этапам.

## Проверки
```sh
npm run lint
npm run typecheck
npm test
npm run build
node tests/integration/store-http.mjs
npm run test:e2e
```
Последняя команда требует браузера Playwright (в Windows — Chrome). Для авторизованного сценария каталога используется отдельный локальный Supabase и тестовый мастер. Перечень выполненных проверок и ограничений приведён в [отчёте Phase 02](docs/PHASE_02.md).
