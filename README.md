# Roomlet · Phase 02.3

Магазин и Studio работают с общим каталогом Supabase. Покупателю доступны магазин и его профиль, а мастер и владелец могут открыть Studio из своего профиля или по прямому адресу. Этап основан на Phase 02.2 (`7335343`), рабочая ветка — `feature/backend-studio`.

## Локальный демонстрационный каталог

В PowerShell откройте основную папку проекта и запустите предпросмотр. Для первого запуска нужны Node.js 22.13+ и зависимости из `package-lock.json` (`npm ci`).

```powershell
Set-Location -LiteralPath "$env:USERPROFILE\Desktop\Frontend\Roomlet"
npm run demo:dev
```

Команда собирает локальную версию в `.roomlet-demo/build/`, затем запускает приложение. После изменения исходников остановите процесс сочетанием `Ctrl+C` и снова выполните `npm run demo:dev`. Правки ассортимента в Studio видны в магазине при обновлении страницы.

Откройте [демонстрационный Store](http://127.0.0.1:3211/), [профиль](http://127.0.0.1:3211/profile) или [Studio](http://127.0.0.1:3211/studio). При первом запуске скрипт поднимает Supabase Lite на `127.0.0.1:54331`, применяет схему и создаёт четыре изделия с двумя фотографиями каждого. Изменения из Studio сохраняются между запусками в `.roomlet-demo/`.

### Проверка ролей

`npm run demo:dev` готовит три учётные записи в локальном Supabase. В файле `.roomlet-demo/accounts.json` хранится JSON-массив записей с полями `role`, `email` и `password`. Файл исключён из Git. Чтобы увидеть гостевой экран, откройте профиль в приватном окне браузера.

| Роль | Доступ в профиле |
| --- | --- |
| Гость | Вход по почте, избранное и история демозаявок этого устройства |
| Покупатель (`customer`) | Избранное, история, настройки имени и выход |
| Мастер (`maker`) | Все разделы покупателя и карточка Roomlet Studio |
| Владелец (`owner`) | Возможности мастера и управление командой |

Для проверки роли откройте [форму входа](http://127.0.0.1:3211/profile/login). Следующие команды показывают почту и копируют пароль выбранной тестовой записи в буфер обмена. Замените `maker` на `owner` или `customer` для другого сценария.

```powershell
$demoAccounts = Get-Content -LiteralPath .roomlet-demo/accounts.json -Raw | ConvertFrom-Json
$demoAccount = $demoAccounts | Where-Object role -eq 'maker'
$demoAccount.email
Set-Clipboard -Value $demoAccount.password
```

Для Store и Studio действует одна сессия Supabase. Сервер подтверждает пользователя через Auth и читает роль из `profiles`. Для проверки другой роли выйдите из аккаунта или откройте отдельный профиль браузера.

Раздел «Мои заказы» в демоверсии содержит сохранённые на устройстве заявки и индивидуальные проекты. Бронирования, уведомления и связь с мастерской пока помечены как недоступные. Отправка писем из локальной Studio отключена. Владелец может назначить мастером существующего подтверждённого пользователя и отозвать доступ у мастера.

### Удаление и восстановление примеров

Выполните `npm run demo:clean` в корне Roomlet. Команда проверяет фиксированные идентификаторы и метку `is_demo`, удаляет соответствующие записи, связанные фотографии и освободившиеся категории примеров. Очистка действует только в локальном предпросмотре. Обновите [демокаталог](http://127.0.0.1:3211/catalog), чтобы проверить результат. После перезапуска он останется очищенным.

Чтобы восстановить комплект, выполните `npm run demo:seed`. Повторный запуск сохраняет внесённые мастером изменения в существующих образцах. Обе команды можно выполнять в отдельном терминале при работающем предпросмотре или после его остановки. [Источники и условия использования изображений](docs/IMAGES.md).

## Рабочий магазин

1. Используйте Node.js 22.13+ и выполните `npm ci`. Скопируйте `.env.example` в `.env.local`, задайте URL проекта и его publishable key. Для рабочей витрины оставьте `ROOMLET_DEMO_MODE=false`.
2. Для первой настройки и согласованных изменений рабочей базы используйте [инструкцию подключения](docs/SETUP.md). Первоначальную роль владельца назначает администратор проекта после проверки UID и разрешения на изменение.
3. Выполните `npm run dev`. Откройте [магазин](http://localhost:3000), [профиль](http://localhost:3000/profile) или [Studio](http://localhost:3000/studio). На телефоне используйте адрес доступного ему сервера. Для установки на хостинг выполните `npm run build` и `npm start`, задав те же переменные среды на сервере.

## Первый товар

Войдите в Studio, откройте «Изделия», создайте карточку и добавьте фотографии. Укажите категорию, цену, запас готовых экземпляров или возможность изготовления. Сохраните черновик, проверьте карточку и опубликуйте. Изменения видны при следующем открытии каталога. В разделе «Настройки» задаются часовой пояс, валюта, рабочие часы по дням недели, резерв и периоды недоступности.

## Режимы

Рабочая витрина на порту `3000` читает опубликованные карточки подключённого проекта Supabase. Пустой каталог и ошибка подключения имеют разные состояния. `npm run demo:dev` сам задаёт параметры локального режима для процесса предпросмотра на порту `3211`. Производственная сборка этот режим не включает. Оба варианта Studio проверяют серверную сессию и роль `owner` или `maker`.

## Проверки

```sh
npm run lint
npm run typecheck
npm test
npm run build
node tests/integration/store-http.mjs
npm run test:e2e
```
Для E2E в Windows требуется Chrome. Чтобы проверить вход для всех ролей, запустите демоверсию и выполните в отдельном PowerShell из корня проекта следующие команды. Тесты используют локальные аккаунты из `.roomlet-demo/accounts.json`.

```powershell
$env:ROOMLET_TEST_URL = 'http://127.0.0.1:3211'
npm run test:e2e
```
